Executive Summary

AppBase is in notably good shape for a template: helmet with a Clerk-aware CSP and no unsafe-inline scripts, synchronizer-token CSRF wired end to end (server middleware + client retry helper), layered rate limiting, structured logging with sanitized request IDs, encrypted committed env files, SHA-pinned CI actions, and a small, well-tested vendored session store. TypeScript strict mode is on for both server and client, and the documented theme persistence keys (dal.theme.mode / dal.ui.style) match the code exactly.

The most important finding (High) is that the production boot guard for SESSION_SECRET only checks string length, not whether dotenvx decryption actually happened. If .env.keys is missing on a host, the app silently runs with the committed encrypted:… literal — a publicly known value — as its session-signing secret. The codebase already contains the exact guard for this failure mode for Clerk keys, so the fix is small. Because every derived app copies this config file, the gap propagates org-wide.

Medium findings: every anonymous request (including /healthz load-balancer probes) creates a persisted session row because CSRF token generation runs globally; the env-file resolver can silently fall back to .env.production outside production; the React shell has no error boundary; two AGENTS.md-documented UI contracts (stale-client banner, toasts) ship CSS but no implementation; and the ASCII canvas background repaints every cell at uncapped display refresh rate.

Security Findings (8)

HighDone SESSION_SECRET accepts an undecrypted dotenvx literal in production

server/config.ts:88–93  ·  contrast: server/clerkEnv.ts:21–38  ·  .env.production:22

The production guard for SESSION_SECRET only validates length. When the dotenvx private key is unavailable (missing or wrong .env.keys / DOTENV_PRIVATE_KEY_*), dotenvx leaves the raw encrypted:BAN+zFxs… string in the environment. That string is far longer than 32 characters, so the check passes and the server boots using a value that is committed to the repository — i.e. public — as its session-signing secret.

const envSessionSecret = process.env.SESSION_SECRET?.trim() || '';
if (NODE_ENV === 'production' && envSessionSecret.length < 32) {
  throw new Error('[FATAL] SESSION_SECRET must be set and at least 32 characters in production.');
}
export const SESSION_SECRET = envSessionSecret || DEFAULT_SESSION_SECRET;

The codebase itself proves this failure mode is real and anticipated — server/clerkEnv.ts has an explicit guard for exactly this, but only for the Clerk keys:

if (isEncryptedEnvValue(value)) {
  throw new Error(
    `[FATAL] ${name} is still encrypted. Ensure DOTENV_PRIVATE_KEY_* is available (see .env.keys) or run via dotenvx.`,
  );
}

Impact: With a known session secret, an attacker can forge signed express-session cookies, mint sessions with arbitrary CSRF tokens, and fully bypass CSRF protection. Because server/config.ts is copied into every derived app (Armory, Codex, BudgetPlanner), a single misdeployed host in any app inherits this silently — elevating what would otherwise be a deployment mistake into a template-level defect.

Recommendation: Reuse isEncryptedEnvValue() from clerkEnv.ts in config.ts and fail boot (in any NODE_ENV) when SESSION_SECRET still starts with encrypted:. Apply the same fix in the three derived apps.

MediumDone Every anonymous request creates a persisted session — including health probes

server/app.ts:88, 111–116, 163–174  ·  server/db/sqliteSessionStore.ts:73–85

The CSRF token-generation middleware runs globally on all routes, and generateToken(req) writes the token into the session. This marks the session as modified, which defeats saveUninitialized: false: every cookieless request — static assets, SPA page loads, crawlers, and notably /healthz / /readyz (registered after this middleware) — inserts a session row and emits Set-Cookie.

app.use(csrfSynchronisedProtection);

app.use((req, res, next) => {
  (res.locals as { csrfToken?: string }).csrfToken = generateToken(req);
  next();
});
// ... /healthz and /readyz are registered later, so they pass through this

Impact: Load balancers typically don't retain cookies, so a probe every 10 seconds accrues ~60,000 rows per week per probe, each kept for the full 7-day cookie maxAge before the cleanup timer removes it. It also hands a session row to every bot hit (cheap disk-fill vector) and adds a synchronous SQLite write to every anonymous GET. Health endpoints answering with Set-Cookie is a smell in itself. Propagates to all derived apps.

Recommendation: Register /healthz and /readyz before the session middleware, and generate CSRF tokens lazily — e.g. only inside GET /api/csrf (the client already fetches it on demand via client/utils/api.ts) instead of on every request.

Low CSRF token is never rotated on authentication state change

server/app.ts:93–109  ·  server/routes/auth.ts:7–14

csrf-sync's generateToken(req) reuses an existing session token by default, and nothing regenerates the express session or the token when a user signs in or out through Clerk. A CSRF token issued to a pre-auth (anonymous) session remains valid for the same browser after sign-in.

Impact: Limited in the current template because authentication lives entirely in Clerk's own cookies and the express session holds only the CSRF token. But derived apps that start storing user data in req.session will inherit a session-fixation-shaped gap without noticing.

Recommendation: Document the constraint, or call req.session.regenerate() + revokeToken()/generateToken(req, true) in an auth-transition hook so derived apps get the safe pattern for free.

Low Session cookie is scoped org-wide although only Clerk/theme cookies need it

server/app.ts:74–80  ·  .env.production:26–30

With production COOKIE_DOMAIN=.darkavianlabs.com, the express session cookie (appbase.sid) is sent to every DAL subdomain. The shared-login goal is achieved by Clerk's cookies and the theme cookie; the per-app session cookie gains nothing from the wide scope — collisions are only avoided by the per-app cookie name.

const cookieOptions: express.CookieOptions = { ... };
if (COOKIE_DOMAIN) cookieOptions.domain = COOKIE_DOMAIN;

Impact: Any compromised or cookie-tossing-capable host under *.darkavianlabs.com can read or fixate the session (and CSRF) cookies of every other app, and each app's session cookie is needlessly attached to cross-subdomain requests. The design is documented as intentional in AGENTS.md, but the blast radius extends beyond what the feature requires.

Recommendation: Keep the session cookie host-only (don't apply COOKIE_DOMAIN to it); reserve the shared domain for the theme cookie and Clerk's own cookie handling.

LowDone getClerkAuthorizedParties silently drops a misconfigured production origin

server/auth/clerkAuthorizedParties.ts:22–24, 42–44

In production, non-https:// origins are filtered out silently. If APP_PUBLIC_BASE_URL is accidentally left as http://… (the .env.example default), the app's own origin is removed from Clerk's authorizedParties with no warning — the presence check at line 31–33 passes, then the filter discards it.

function isAllowedOrigin(origin: string, isDevEnv: boolean): boolean {
  return origin.startsWith('https://') || (isDevEnv && origin.startsWith('http://'));
}
...
].filter((origin) => isAllowedOrigin(origin, isDevEnv));

Impact: Every authenticated request fails authorized-party validation at runtime with no boot-time signal, which is much harder to diagnose than a startup error. (Positive: requiring authorizedParties at all is good hardening.)

Recommendation: Throw at startup when the normalized APP_PUBLIC_BASE_URL is filtered out in production, instead of silently removing it.

LowDone No format validation of Clerk keys — placeholder keys 500 every request

server/auth/middleware.ts:10–12

isClerkConfigured() only checks non-emptiness, so placeholder values like sk_test_placeholder are treated as configured and passed to clerkExpressMiddleware, which then throws on every request. This exact footgun is documented as a known pitfall in the AGENTS.md of all three derived apps — evidence it bites in practice — yet the template doesn't guard it.

export function isClerkConfigured(): boolean {
  return Boolean(process.env.CLERK_PUBLISHABLE_KEY?.trim() && process.env.CLERK_SECRET_KEY?.trim());
}

Impact: A whole-app outage (HTTP 500 on every route) from a config value that looks plausible, with the root cause buried in Clerk middleware internals.

Recommendation: Validate prefixes (pk_test_/pk_live_, sk_test_/sk_live_) and reject known placeholder strings with a clear boot error.

InformationalDone /api/csrf response has no Cache-Control: no-store

server/routes/api.ts:12–15

The CSRF-token endpoint sets no cache headers. In practice the accompanying Set-Cookie deters shared caches, and the token is per-session, so risk is minimal — but security-token endpoints should be explicit.

Recommendation: Add res.setHeader('Cache-Control', 'no-store') to the handler.

Informational Rate limiters use the in-memory store

server/app.ts:59–70, 132–151

All four express-rate-limit instances default to the per-process memory store: counters reset on restart and are not shared across instances. Fine for the current single-process deployments; worth knowing before any derived app scales horizontally.

Recommendation: No change needed now; note the constraint in AGENTS.md so multi-instance deployments swap in a shared store.

Reliability Findings (5)

MediumDone Env resolver silently falls back to .env.production outside production

server/config.ts:17–35

When NODE_ENV is unset with .env.development missing, or set to anything unrecognized (e.g. staging), the resolver's priority list puts .env.production first and loads it without complaint.

const prioritizedFiles = [
  envFileByMode[normalizedNodeEnv],   // undefined for unknown NODE_ENV
  '.env.production',
  '.env.development',
].filter(...);

Impact: A dev or CI machine can silently run with production settings — the org-wide COOKIE_DOMAIN, production APP_PUBLIC_BASE_URL, and production Clerk key slots. Combined with the High finding above, a non-production process that loads .env.production without the private key will run with the encrypted literal as its session secret. Copied by every derived app.

Recommendation: Load only the exact file for the current NODE_ENV and fail (or at minimum log a prominent warning) when it does not exist; never fall back across environments.

Medium No React error boundary anywhere in the client shell

client/main.tsx:11–19  ·  client/app/routes.tsx:36–50

The tree is StrictMode → BrowserRouter → ThemeProvider → App with a Suspense fallback for lazy routes, but no error boundary at any level. A render-time throw in any component — or a failed lazy-chunk import after a redeploy invalidates hashed asset URLs — results in React unmounting the entire tree: a permanent blank page with no recovery path.

createRoot(document.getElementById('root')!).render(
  <StrictMode>
    <BrowserRouter>
      <ThemeProvider>
        <App />
      </ThemeProvider>
    </BrowserRouter>
  </StrictMode>,
);

Impact: Template-wide: every derived app ships without crash containment unless each adds it independently. The stale-chunk case is a routine production event for SPAs, not an edge case.

Recommendation: Ship a top-level error boundary (with a "reload" CTA — this pairs naturally with the already-styled stale-update-banner, see Best Practices) and consider a per-route boundary inside Layout.

LowDone Graceful shutdown waits out keep-alive connections until the timeout

server/index.ts:30–35

server.close() only fires its callback once all connections end, and browsers hold keep-alive sockets open. With any recently active client, shutdown will nearly always burn the full SHUTDOWN_TIMEOUT_MS (10s) before the timer force-exits.

const timeout = setTimeout(closeAndExit, SHUTDOWN_TIMEOUT_MS);
server.close(() => {
  clearTimeout(timeout);
  closeAndExit();
});

Impact: Slow restarts/deploys; the fallback path (hard process.exit) becomes the common path rather than the exception.

Recommendation: Call server.closeIdleConnections() immediately after server.close(), and server.closeAllConnections() shortly before the deadline (both available since Node 18).

LowDone Session-store cleanup timer swallows all errors silently

server/db/sqliteSessionStore.ts:32–39

The periodic clearExpired() catch block ignores every failure. If the session DB enters a persistent error state (disk full, file lock, corruption), expired rows accumulate forever with zero log output.

this.cleanupTimer = setInterval(() => {
  try {
    this.clearExpired();
  } catch {
    // ignore
  }
}, interval);

Impact: Amplifies the anonymous-session-growth finding above: the only pressure-release valve can fail invisibly. Vendored code is copied to all apps.

Recommendation: Accept an optional logger (or emit an event) and log at least the first failure; the store otherwise has no observability hook.

Low dev.mjs gives child processes only 100ms to die (dev-only)

scripts/dev.mjs:19–28

shutdown() sends SIGTERM and calls process.exit() 100ms later. On Windows, child.kill('SIGTERM') is a hard kill of the direct child but the 100ms window can leave grandchild processes (the tsx-watched server, Vite workers) orphaned and holding ports.

for (const child of children) {
  if (!child.killed) child.kill('SIGTERM');
}
setTimeout(() => process.exit(code), 100);

Impact: Occasional orphaned dev servers / "port already in use" friction after Ctrl+C, particularly on Windows. Development-only; the forced SECURE_COOKIES=0 in the same script is correct and intentional.

Recommendation: Wait for child exit events (with a longer deadline) before exiting, or use a process-tree kill on Windows.

Best Practices Findings (4)

Medium AGENTS.md-documented UI contracts (stale-client banner, toasts) have no implementation

client/styles/input.css (24 rule references)  ·  no matches in client/**/*.{ts,tsx}  ·  AGENTS.md “Component contracts” table

AGENTS.md specifies the stale-client banner (stale-update-banner + gold stale-update-cta with the "Refresh" label) and toasts (.toast-pill with data-tone) as component contracts. input.css ships 24 rule references for these classes, but a search of the entire client source finds zero components, hooks, or usages. AppBase is supposed to be the reference implementation sibling apps copy from.

Impact: Derived apps have styling but no canonical behavior to copy (when to show the banner, how version staleness is detected, toast queueing/dismissal). Each app will reinvent it — the exact divergence the design-system contract exists to prevent. Also ~24 dead CSS rule blocks in the template today.

Recommendation: Either add minimal reference components (StaleUpdateBanner, a toast helper) to client/components/ui/, or amend AGENTS.md to state the contract is CSS-only and behavior is app-defined.

LowDone Dead code: closeSessionDb() is never used and its logic is duplicated

server/db/connection.ts:17–22  ·  server/index.ts:21–27

closeSessionDb() has no callers; server/index.ts closes the DB handle directly in its shutdown path, leaving the module-level sessionDb singleton in connection.ts pointing at a closed database.

// connection.ts — never called
export function closeSessionDb(): void {
  if (sessionDb) { sessionDb.close(); sessionDb = null; }
}

Impact: Cosmetic today, but a stale singleton referencing a closed DB is a latent trap for template consumers who later call getSessionDb() during shutdown paths.

Recommendation: Have index.ts call closeSessionDb(), or delete the helper.

LowDone Leftover .prettierrc.json although oxfmt is the formatter

.prettierrc.json  ·  package.json:19–20 (format/check-format use oxfmt)  ·  docs/org-standards/validate.md

The repo's quality gate formats with oxfmt (.oxfmtrc.json), but a .prettierrc.json is also committed. Editors and IDE plugins that auto-detect Prettier will format with different rules than pnpm run check-format enforces.

Impact: Contributor churn: locally "formatted" files fail CI's format check. Template consumers copy the ambiguity.

Recommendation: Delete .prettierrc.json (or document why it must remain, e.g. for a tool oxfmt doesn't cover).

Low No tests for client UI primitives with non-trivial logic

client/lib/scaffoldSearch.test.ts (only client test)  ·  untested: client/components/ui/Modal.tsx:49–105, SelectDropdown.tsx:79–148

Server coverage is genuinely good (app integration, session store, schema). On the client, only scaffoldSearch is tested. The Modal's focus trap / focus restore and the SelectDropdown's positioning + keyboard state machine are the most intricate client logic in the template and are exactly the pieces AGENTS.md tells sibling apps to keep byte-for-byte in sync.

Performance Improvements (4)

Medium ASCII canvas repaints every cell of both layers at uncapped refresh rate

client/lib/asciiBackground/drawAsciiOverlayFrame.ts:34–68  ·  useAsciiBackgroundCanvas.ts:120–125

The animation loop runs a bare requestAnimationFrame chain (no FPS cap), and every frame clears the canvas and re-renders the entire static base layer glyph-by-glyph with per-cell fillText, then walks all rows×cols a second time computing the scan-band blend per cell.

ctx.clearRect(0, 0, w, h);
for (let r = 0; r < rows; r++) {
  ...
  for (let c = 0; c < cols; c++) {
    const ch = rowBase[c] ?? ' ';
    ctx.fillText(ch, c * cellW, y);   // static layer, redrawn every frame
  }
}

Impact: Continuous CPU cost on every page of every derived app, scaling with display refresh rate (144Hz screens do 144 full repaints/s of unchanged content) — measurable battery drain on laptops. Mitigations already present: rAF auto-throttles in hidden tabs, and prefers-reduced-motion paints a single static frame.

Recommendation: Render the static base layer once to an offscreen canvas and drawImage it per frame; restrict the per-cell blend loop to the moving scan band's bounding box; cap the animation at ~30fps. The wave period is 22s, so lower frame rates are visually indistinguishable.

Low Five variable font families imported unconditionally

client/styles/input.css:2–6

Cascadia Mono, Inter, Geist, Geist Mono, and Material Symbols Rounded variable fonts are all imported globally. Variable fonts — the icon font especially — are multi-hundred-KB woff2 payloads each, fetched on first visit regardless of how many the page actually renders.

@import '@fontsource-variable/cascadia-mono';
@import '@fontsource-variable/inter';
@import '@fontsource-variable/geist';
@import '@fontsource-variable/geist-mono';
@import '@fontsource-variable/material-symbols-rounded';

Impact: Inflated first-load network weight and font-swap flashes for every derived app; most templates use one to two of these per page (Geist UI text + Cascadia for the canvas).

Recommendation: Audit which families each surface really needs, drop or lazy-load the rest, and consider a subset icon strategy for Material Symbols.

Informational Acrylic UI style's backdrop filter is expensive by design

client/styles/input.css (html.ui-acrylic blocks)  ·  AGENTS.md “UI style overrides”

blur(40px) saturate(200%) contrast(1.08) backdrop filters on all glass surfaces, plus exclusion-blend grain and tiled noise, are heavy compositing work. This is a signed-off, opt-in design decision (Prism is the default), and the CSS correctly avoids stacking blur on #root while a modal is open — so this is a note, not a defect.

Recommendation: None required; keep Acrylic opt-in and keep the documented restriction against adding brightness().

Informational Synchronous SQLite I/O on the request path

server/db/sqliteSessionStore.ts:53–105  ·  server/db/connection.ts:10–12

better-sqlite3 is synchronous, so each session read/write blocks the event loop briefly. WAL mode and busy_timeout = 5000 are correctly configured, and at the scale these apps run this is a sound simplicity trade-off — flagged only so derived apps under heavier load know where the ceiling is.

Recommendation: None at current scale.

UX Improvements (4)

Secondary category — listed separately from the primary audit findings above.

Low SelectDropdown loses keyboard focus on close and lacks standard listbox keys

client/components/ui/SelectDropdown.tsx:171–184, 226–233, 256–265

Options live in a portal; on Enter/Escape/click the menu unmounts while an option button holds focus, so focus falls to <body> — it is never returned to the trigger button. The trigger also doesn't open on ArrowDown/ArrowUp (the native <select> convention), and the listbox lacks Home/End/typeahead.

if (e.key === 'Enter' || e.key === ' ') {
  e.preventDefault();
  const opt = displayOptions[focusedIndex];
  if (opt) { onChange(opt.value); onOpenChange(false); }  // focus not restored
}

Impact: Keyboard users are dropped to the top of the tab order after every selection. This primitive is a documented cross-app contract, so the gap ships to Armory/Codex/BudgetPlanner too. Otherwise the ARIA wiring (roles, aria-expanded, aria-selected, roving tabindex) is solid.

Recommendation: Call buttonRef.current?.focus() when closing, and add ArrowDown/ArrowUp-to-open plus Home/End.

Low Settings menu has no focus management or menu semantics

client/components/Layout/Layout.tsx:66–82  ·  client/components/ui/Menu.tsx:9–19

Menu renders a plain styled div. The Layout's settings popover handles outside-click and Escape, but opening it does not move focus into the menu, closing does not restore focus to the gear button, and there are no menu/arrow-key semantics for the popup.

Impact: Screen-reader users get no announcement that a popup opened; keyboard users must Tab hunt for it. Currently low impact (one item — the UI style selector) but this is the shared user-menu shell contract for all apps.

Recommendation: Move focus to the first interactive element on open, restore to the trigger on close; aria-expanded/aria-controls are already present, which helps.

Low Modal has no accessible-name fallback

client/components/ui/Modal.tsx:141–151

ariaLabelledBy is optional and there is no aria-label alternative, so a caller that omits it produces an unnamed role="dialog" — screen readers announce only "dialog".

<div ref={modalRef} className={modalClassName} role="dialog"
     aria-modal="true" aria-labelledby={ariaLabelledBy} tabIndex={-1}>

Impact: Template consumers get silent a11y regressions for every unlabeled dialog. The focus trap, focus restore, Escape handling, and nested-modal counting in this component are otherwise well done.

Recommendation: Add an ariaLabel prop and (in dev) warn when neither naming prop is provided.

Low SearchBar results are not a keyboard-navigable combobox

client/components/Layout/SearchBar.tsx:55–74, 91–96

The input declares aria-autocomplete="list" and aria-expanded, implying a combobox, but the results container is role="region", there is no role="combobox"/listbox/option structure, no aria-activedescendant, and ArrowDown/ArrowUp do not move through results (only Enter-for-first-match and mouse work). aria-controls also references an element that doesn't exist while the popup is closed.

Impact: Assistive tech is told a listbox pattern exists but gets none of its behavior. Low today (four static scaffold pages) but this is the search pattern derived apps will extend with real data.

Recommendation: Implement the WAI-ARIA combobox pattern: role="combobox" on the input, role="listbox"/option in the popup, arrow-key selection with aria-activedescendant.

Positive Observations

  • SESSION_SECRET / boot guards are mostly strong: production enforces a ≥32-char secret (server/config.ts:90), requires Clerk keys with an explicit still-encrypted check (server/clerkEnv.ts), and refuses SECURE_COOKIES without TRUST_PROXY (server/app.ts:48–50).
  • CSP without script unsafe-inline: helmet keeps default directives and only whitelists the Clerk FAPI origin and Cloudflare Turnstile (server/http/helmetCsp.ts); theme-init.js is an external file precisely so no inline script is needed.
  • theme-init.js is XSS-safe: cookie/localStorage values are validated against strict whitelists (light|dark, four UI styles) before touching classList — no injection path (public/theme-init.js:21–62).
  • Vendored session store is clean and tested: parameterized SQL throughout, correct fixed-width ISO-8601 expiry comparisons, upsert semantics, touch/all/length implemented, unref'd cleanup timer, and a thorough unit suite (sqliteSessionStore.test.ts) — a genuine improvement over the unmaintained npm package it replaces.
  • CSRF is wired end to end: synchronizer-token middleware server-side with a distinct X-CSRF-Error signal, plus a client helper that caches, retries once on rejection, and clears the token on sign-out (client/utils/api.ts).
  • CI hygiene matches org standards: actions pinned to commit SHAs with Dependabot maintenance, --frozen-lockfile, pnpm audit --audit-level high, Blacksmith 8vcpu runner, single pnpm run validate step (.github/workflows/pr.yml).
  • AGENTS.md contracts verified accurate for theme persistence keys (dal.theme.mode/dal.ui.style with appbase.theme.mode fallback), boot order (SSR class fallback → sync theme-init → ThemeProvider with first-write skip), ports, and component class names (88 references for spot-checked tokens/classes in input.css).
  • prefers-reduced-motion respected in both backgrounds: the ASCII canvas paints a single static frame (and re-paints on theme change via MutationObserver), and hex pulses freeze (useAsciiBackgroundCanvas.ts:58,113–118; HexSideBackground.tsx:93,114–122).
  • Sensible server hardening baseline: 100kb body limits, layered rate limits, sanitized request IDs (regex-validated echo), structured JSON logs, JSON 404 for unknown API routes, error handler that never leaks internals for 5xx, and denied client build returns 503 rather than crashing.
  • Client code quality: TypeScript strict everywhere, route-level code splitting, memoized ThemeContext value (no unnecessary re-renders), safe localStorage access wrappers, and Modal's nested-dialog counting via data-modal-open-count matches the documented design.
